# Judo Analytics

유도 경기 영상을 분석해 기술 후보와 경기 중 점수 판정의 근거를 타임라인으로 보여주는 웹 애플리케이션을 만드는 프로젝트입니다. 사용자가 MP4를 업로드하면 영상에서 관련 장면을 찾고, 기술·점수의 **AI 추정 결과**를 근거 프레임 및 시간 정보와 함께 확인할 수 있도록 하는 것이 목표입니다.

> 이 서비스의 결과는 경기 심판의 공식 판정이 아닙니다. 영상에서 확인할 수 있는 정보가 충분하지 않거나 판정이 모호하면 `불확실` 또는 사람 검토 대상으로 표시하는 것을 기본 원칙으로 합니다.

## 프로젝트 상태

**학습된 기술 추천 모델을 기존 영상 분석 화면과 워커에 연결했습니다.** 사용자가 30초 이내 공격 구간을 선택하면 4종 기술 중 후보 3개를 추천하고, 착지·득점은 사용자가 확인합니다. 모델 결과와 사용자 확인값을 분리 저장합니다.

현재 구현·검증·배포 방법은 [모델 연결 현황](docs/architecture/model-integration.md), 최신 범위는 [축소 PRD](PRD-judo-analysis-mvp.md)를 참고하세요. 새 DB 마이그레이션과 모델 포함 워커 배포, Blob·Cloud Tasks 환경 설정이 필요합니다. 별도의 자연어 채팅창은 현재 없습니다.

**아래의 초기 설계·공유 비밀번호·미연결 상태 설명은 과거 기록이며 현재 실행 안내가 아닙니다.** 현재 인증은 Supabase Google/Kakao와 회원 Workspace/RLS를 사용하고, 실제 실행 설정은 [.env.example](.env.example) 및 [배포 문서](docs/deployment/cloud-stack.md)를 따릅니다.

현재 저장소에 준비된 내용:

- `.opencode/skills/judo-analysis-planning/SKILL.md` — 제품 범위와 구현 순서
- `.opencode/skills/judo-data-labeling/SKILL.md` — 데이터 권리, 라벨링, 데이터셋 구성
- `.opencode/skills/judo-video-pipeline/SKILL.md` — 영상 처리 및 모델 연동
- `.opencode/skills/judo-web-platform/SKILL.md` — Next.js·Vercel 웹 플랫폼
- `.opencode/skills/judo-analysis-evaluation/SKILL.md` — 평가, 배포, 운영 기준

이 지침들을 구현 기준으로 삼고, 모델·데이터 처리 기능은 권리와 판정 범위가 확인된 뒤 단계적으로 추가합니다.

### 현재 동작하는 기능

- Next.js App Router 기반 한국어 웹 UI와 MP4 로컬 미리보기
- 8시간 유효한 공유 접근 비밀번호 쿠키(계정별 사용자 인증은 아님)
- 접근 권한이 있는 경우 최대 500 MB MP4의 Vercel Blob 비공개 업로드
- 분석 API와 모델 어댑터 인터페이스. 미연결 상태에서는 `MODEL_NOT_CONFIGURED`를 반환하며 점수나 기술을 지어내지 않음
- 업로드 성공/분석 미구성 상태를 사용자에게 명확히 표시

공유 비밀번호는 제한된 프로토타입용 보호 수단입니다. 공개 서비스 전에는 계정별 인증, 사용자 소유권, 요청 제한 및 사용량 관리가 필요합니다.
현재 업로드 검증은 파일명/브라우저 MIME 및 Blob 업로드 제한에 의존하며, FFprobe를 통한 실제 컨테이너·코덱·영상 길이 검사는 아직 없습니다. 업로드된 영상의 삭제 기능도 아직 없습니다.

### 아직 동작하지 않는 기능

- 영상 프레임 추출, FFmpeg 처리, 기술 탐지 또는 실제 점수 판정
- 학습 영상 수집, 라벨링, 데이터셋 관리, 모델 학습/파인튜닝
- 분석 작업 큐, 장시간 백그라운드 워커, 재시도 및 영속적인 작업 상태/결과 저장
- 업로드 파일 삭제 UI/API, 사용자별 보관 정책
- 정식 사용자 계정/권한 관리와 성능 평가 파이프라인

## 구현 목표 기능

### MVP 목표

1. 사용자가 인증된 웹 화면에서 허가된 MP4 영상을 업로드합니다.
2. 업로드 영상의 형식, 크기, 길이, 해상도 등 처리 가능 여부를 확인합니다.
3. 백그라운드 작업이 영상을 분석하고, 유도 동작이 발생한 후보 구간을 찾습니다.
4. 후보 구간별로 다음 정보를 제공합니다.
   - 영상 내 시간대와 재생 가능한 근거 장면
   - 유도 기술명 또는 `판별 불가`
   - 적용 규정에서 정의하는 점수 후보: 한판(ippon), 절반(waza-ari), 유효(yuko), 무득점 또는 불확실
   - 판단에 사용된 관찰 근거와 확인할 수 없었던 정보
   - 규정 버전, 분석 모델/버전, 사람 검토 여부
5. 분석 중·완료·실패 상태를 보여주고, 오류 작업을 재시도하거나 결과를 검토할 수 있게 합니다.
6. 권한이 있는 사용자가 영상과 파생 데이터의 삭제를 요청할 수 있도록 합니다.

점수 값은 모든 대회에 고정된 목록으로 적용하지 않습니다. 대회·연령·시기별 적용 규정을 확인하고, 분석 결과마다 규정 버전을 기록합니다. 최종 경기 결과를 제공하려면 점수판, 주심 신호, 경기 시간, 누적 벌칙, 누르기 시간 등 영상에 표시되거나 확인 가능한 맥락이 필요한지 별도로 정의해야 합니다.

### 기술 구성 방향

- **웹 앱:** Next.js App Router, TypeScript
- **배포:** Vercel
- **영상 저장:** 비공개 객체 저장소(예: Vercel Blob private store)
- **영상 처리:** FFprobe/FFmpeg로 메타데이터를 확인하고 시간 정보가 있는 프레임/구간 추출
- **AI:** OpenAI API의 현재 모델 및 이미지 입력 기능을 우선 검토. 모델의 실제 영상 입력 지원 여부와 한도는 구현 시점의 공식 문서에서 확인
- **비동기 처리:** 업로드 요청과 분석을 분리하고, 큐와 백그라운드 워커에서 장시간 영상 처리
- **데이터:** 데이터베이스에 사용자 소유권, 영상 메타데이터, 작업 상태, 결과, 규정/모델 버전 기록
- **결과 형식:** 고정된 스키마로 응답을 검증하고, 타임스탬프·규정·영상 구간에 맞는지 서버에서도 확인

큰 영상은 Vercel 함수에 직접 전달해 처리하지 않습니다. 브라우저에서 비공개 저장소로 직접 업로드하고, 작업 큐가 별도 워커에 분석을 맡기는 구조를 검토합니다. 워커는 Vercel의 현재 상품·플랜 지원과 처리 요구사항을 확인한 뒤 Vercel Daemon 또는 별도 컨테이너/GPU 서비스 중 선택합니다.

## 기존 영상과 모델 학습

기존 영상 파일을 모델에 연결한다고 모델이 자동으로 학습되는 것은 아닙니다. 영상은 다음 중 어떤 목적으로 쓸지 구분해야 합니다.

- **학습 데이터:** 전문가가 기술 종류, 이벤트 구간, 판정, 적용 규정 등을 라벨링한 영상
- **검색/참고 데이터:** 분석 시 비슷한 예시를 찾아 참고하는 영상
- **평가 데이터:** 모델 결과를 전문가 정답과 비교하는 별도 보류 데이터

프레임만 듬성듬성 추출하면 빠른 기술의 공격·착지 순간을 놓칠 수 있습니다. 시간 순서를 보존한 장면 추출과 전문가 판정이 필요합니다. 같은 경기의 인접 프레임이 학습 데이터와 시험 데이터에 나뉘지 않도록 경기 단위로 데이터를 분리합니다.

## 영상 권리 및 유튜브 이용 정책

유튜브에 공개된 영상이라고 해서 다운로드, 프레임 추출, 모델 학습, 클라우드 저장 또는 상용 서비스 이용 권한까지 주어지는 것은 아닙니다. 유튜브 이용약관은 서비스가 명시적으로 허용하거나 사전 서면 허가가 있는 경우 외에 콘텐츠의 다운로드·복제·수정 등을 제한합니다. 올림픽 중계·하이라이트는 IOC뿐 아니라 방송사 등 다른 권리자가 관련될 수 있습니다.

따라서 이 프로젝트는 **권리 확인이나 필요한 허가 없이 유튜브 올림픽 하이라이트를 내려받거나 수집해 학습·평가 데이터로 사용하지 않습니다.** 유튜브 API/임베드 사용과 영상 원본을 추출해 학습하는 것은 별개의 문제입니다. 허가를 받는 경우에도 허가 범위에 다운로드, 프레임/클립 가공, AI 학습·평가, 클라우드/API 전송, 서비스 제공, 보관 기간이 포함되는지 확인하고 기록해야 합니다. 직접 촬영한 영상, 권리가 확인된 데이터셋, 권리자와 서면 계약한 영상이 우선 대안입니다.

이 내용은 일반적인 프로젝트 지침이며 법률 자문은 아닙니다. 실제 수집·학습·상용화 전에 해당 영상의 권리자 및 관련 법률 전문가에게 확인합니다.

## 구현 범위와 제외 범위

### 구현할 목표

- MP4 업로드 및 안전한 비공개 저장
- 비동기 영상 분석 작업과 상태 조회
- 유도 기술 및 점수 판정 **후보**와 근거 타임라인 제공
- 지원 규정 버전 표시, 불확실 결과와 사람 검토 경로
- 전문가가 라벨링한 권리 보유 데이터로 성능 평가
- 사용자 권한 확인, 업로드 제한, 데이터 보관/삭제 절차
- Vercel에 웹 앱 배포하고 별도 워커를 연계하는 구조

### 현재 구현되지 않은 기능

- FFmpeg 영상 처리와 기술/점수 분석 모델
- 학습·검증·시험용 라벨 데이터셋
- 계정별 인증, 데이터베이스, 큐, 워커, 모니터링 및 정식 Vercel 운영 설정
- 정확도·비용·처리시간 측정 결과

## 로컬 실행

Node.js 20.9 이상이 필요합니다.

```bash
npm install
```

`.env.example`을 참고해 `.env.local`을 만들고 다음 값을 설정합니다.

```dotenv
JUDO_UPLOAD_PASSWORD=긴-임의-비밀번호
JUDO_SESSION_SECRET=최소-32자-이상의-임의-비밀값
BLOB_READ_WRITE_TOKEN=Vercel-Blob-읽기쓰기-토큰
```

Vercel Dashboard에서 Blob store를 만들고 개발 환경용 토큰을 설정해야 업로드가 동작합니다. 설정 없이도 UI는 실행되지만, 업로드 API는 오류를 표시합니다. 이 초기 버전은 분석 결과를 저장하지 않으며 모델이 연결되지 않았다는 상태만 반환합니다.

```bash
npm run dev
```

품질 검사:

```bash
npm run typecheck
npm run lint
npm run build
```

### 프로젝트가 자동으로 하거나 보장하지 않을 내용

- **공식 심판 판정 대체:** AI 결과는 공식 경기 결과가 아니며, 현 단계에서 판정 자동화의 정확도나 공인 여부를 보장하지 않습니다.
- **무허가 영상 수집:** 유튜브 크롤링/다운로드, 방송 영상 추출, 권리 미확인 영상의 학습·평가 사용은 구현 범위에 포함하지 않습니다.
- **자동 모델 재학습:** 사용자가 영상을 올리는 것만으로 모델이 업데이트되게 하지 않습니다. 데이터 권리, 전문가 라벨링, 검증 및 별도 승인 절차 없이는 학습에 사용하지 않습니다.
- **선수 신원 식별:** 얼굴 인식이나 선수의 실명·신원 추정은 목표 기능이 아닙니다. 경기 안에서만 통용되는 익명 역할(예: 청/백)을 사용합니다.
- **실시간 심판 보조:** 초기 MVP는 업로드된 영상의 사후 분석을 대상으로 하며, 실시간 스트리밍·실시간 판정은 범위 밖입니다.
- **모든 규정·모든 촬영 조건 지원:** 규정과 영상 품질이 검증된 범위부터 지원하며, 미지원 규정이나 근거 부족 영상은 불확실/미지원으로 처리합니다.

## 권장 구현 순서

1. 지원 대회·연령·규정 버전과 “판정 결과”의 의미 확정
2. 영상 권리/사용 허가 확인 및 전문가와 라벨 기준 작성
3. 소규모 권리 보유·전문가 라벨 영상으로 오프라인 분석 가능성 검증
4. 업로드, 비공개 저장소, DB, 작업 큐, 분석 워커 및 결과 화면 구현
5. 경기 단위로 분리한 보류 데이터에서 기술별·점수별 성능, 오판율, 불확실 비율, 비용 및 처리시간 평가
6. 전문가 검토(shadow mode)를 거쳐 제한적으로 배포하고, 품질과 규정 변경을 지속 모니터링
